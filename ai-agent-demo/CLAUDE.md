# 本文件夹的规则（给 Claude Code 等 AI 智能体看）

这里是《游戏叙事》第三讲的 Twine 故事，用 Twee 3 纯文本保存，故事格式是 Harlowe 3。你的任务是帮老师和学生改写叙事、加属性和记录、做检查。改动必须让故事在 Twine 里照样能玩。

## 能改什么
- 可以改正文、加片段、加链接、加记录（变量）和条件。
- 角色属性用 datamap，道具用 array，玩家做过的事记在 `$log`（array）。三样都在带 `[startup]` 标签的“初始化”片段里统一建好。
  - 例：`(set: $aqing to (dm: "trust", 2, "mood", "平静"))`、`(set: $items to (a: "箱子"))`、`(set: $log to (a:))`
  - 改：`(set: $aqing's trust to it - 2)`、`(set: $items to it + (a: "名片"))`、`(set: $log to it + (a: "做了某事"))`
  - 读：`(if: $aqing's trust >= 2)[…]`、`(if: $items contains "名片")[…]`、`(print: $aqing's mood)`、`(for: each _e, ...$log)[<br>· _e]`

## 不能改什么
- 不推翻故事前提：例如“答应三点前交接”“救人就会迟到”。
- 不改原文件 `StoryData` 里的 `ifid` 和起点片段名。另存成新文件时，把 `StoryTitle` 改成新名字，并给 `ifid` 换一个新的大写 UUID，否则导入 Twine 时会和原故事互相覆盖。
- 除非明确要求，不加第三个选项，不加新人物。
- 代码部分只用英文半角符号；台词可以用中文引号，但只能写在方括号 `[ ]` 或普通正文里。
- 几个条件句挨在一起时，用 `{ }` 把它们包起来，避免没触发的条件留下空行；需要换行处写 `<br>`。

## 改完必须做的事
1. 运行 `python3 tools/check_twee.py <改过的文件>`，结果要显示“通过”。
2. 每加一个记录（包括属性表里的每一项属性），都要说明在哪个片段读它；写了却不读的不要留下。检查脚本只查整个记录，查不到属性表里的单项，这一条要你自己保证。
3. 最后用三五行告诉用户：改了哪些片段、新增了哪些记录、两条测试路线各应该看到什么。
4. 新文件另存，不要覆盖 `起点/` 和 `结果/` 里的原文件。
